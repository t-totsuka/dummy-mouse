## Implementation Notes
- 1.1: golang.org/x/sys の最新版（v0.50.0）が go 1.26 を要求するため、go.mod の go の指定を 1.26.0 にした（steering の tech.md と design.md も更新済み）。依存はルートの tools.go（ビルドタグ tools）で固定している。go.mod / go.sum は 1.1 以外のタスクで編集しない
- 1.2: fakeClock の Advance は、期限が来たタイマーを期限順に発火させる（発火で渡す時刻は Advance 後の now）。起こされた goroutine が登録し直したタイマーは、同じ Advance の中では発火しない。Runner のテストは、PollInterval / StepDelay 以下の幅で BlockUntil と Advance を交互に呼ぶこと。fakeMouse の SetOnMoveTo フックの中で SetPos を呼んでも、MoveTo が成功すると上書きされる。ステップの間のカーソルのずれは、「BlockUntil → SetPos → Advance」で表現すること
- 2.1: `-h` / `-help` は使い方を日本語のエラーとして返す。main ではほかの不正なオプションと同じく、ダイアログを出して exit 2 で終わる扱いになる
- 2.2: Tracker.LastActivity は monotonic 時計の値を持たない time.Time を返す。時刻の比較には == ではなく Equal / Before / Sub を使うこと
- 2.3: 開始位置が画面の範囲外にあるときは、まず開始位置を範囲内に収め、その位置を基準に 4 つの目標を計算する
- 2.4: runner_test.go の advanceTo / waitPending / earliestDeadline は、タイマーを期限ちょうどに発火させるテスト用ヘルパー。Runner の後片付け（finishLap）は defer で動き、1 周が打ち切られても lastLapEnd と lastSeen を必ず更新する。途中で取りやめるかどうかの判定は、runLap のステップのループの中で、StepDelay の wait のあとに入れる
- 2.5: 1 周の途中で CursorPos が失敗したときは、取りやめの条件 (a)（Tracker の時刻）だけで判定して 1 周を続ける。本物の操作はフック → Tracker の経路で検知する前提
- 3.1: 実機テストは MOUSEMOVER_INTERACTIVE=1 のときだけ動く（requireInteractive）。ダイアログのテストは、さらに MOUSEMOVER_DIALOG=1 も必要。Win32 の構造体の配置は、user32_windows_test.go で amd64 の Sizeof / Offsetof を確かめている
- 3.2: 絶対座標の正規化は ((x-origin)*65535 + span/2)/span（span = 幅 - 1）。Windows の実際の対応付け（切り捨て）とは 1px ずれることがあり、そのときは SetCursorPos で補正する。6.2 の実機確認で、補正がどのくらい起きるか、補正分のフックイベントが IsOwnInput で除外されるかを確かめること。補正が多ければ、正規化を ceil((x-origin)*65536/幅) に変えることを検討する
- 3.3: フックはプロセスに 1 つだけ（2 回目の StartHook はエラー）。コールバックは sync.Once で 1 回だけ作る。フックのスレッドでは UnlockOSThread を呼ばない（レビューの提案を受けて修正。unhook に失敗しても、スレッドの終了で OS がフックを外す）。onActivity はすぐに戻る処理にすること。実機での動作は 6.2 で確認する
- 4: Windows の systray.Quit は、onExit をクリックの goroutine で呼ぶ。そのため tray.Run は OnQuit を sync.Once で包み、OnQuit が終わってから戻るようにした（レビューで差し戻され、修正済み）。イベントループが異常終了した場合は、OnReady が呼ばれないまま OnQuit が呼ばれることがある。main の OnQuit は、Runner が起動していない場合でも待ち続けないこと
- 5.1: main の処理は run(args, deps) にまとめ、deps に関数を差し込んでテストする。OnQuit は Runner の終了を最大 5 秒待ち、hook.Stop のエラーは無視する（ログを出さない設計のため）
- 5.2: -trimpath を付けると、ビルド情報から -ldflags が消える（go version -m で -H=windowsgui を確かめられない）。そのため付けていない
- 6.1: この環境には C コンパイラーがなく、-race は実行できない（Tracker の並行性のテストは振る舞いだけを確かめている）。gcc がある環境で `CGO_ENABLED=1 go test -race ./...` を実行すること
