# 技術スタック

## アーキテクチャ

Windows API を直接呼ぶ、単一プロセスのタスクトレイ常駐アプリ。仕組みは「マウスフック（補助としてポーリング）でアイドルを検知 → 時間が来たらマウス入力を送る」というシンプルなループ。OS 依存の処理は薄いアダプター層に閉じ込め、判定ロジックは OS に依存しない純粋なコードにしてテストできるようにする。

## コア技術

- **言語**: Go（1.26 以上。golang.org/x/sys の最新版が go 1.26 を要求するため）
- **対象 OS**: Windows 10 / 11（x64）
- **OS 連携**: `golang.org/x/sys/windows` 経由で `user32.dll` を呼ぶ（`GetCursorPos`, `SendInput`, `SetWindowsHookExW` など）
- **タスクトレイ**: `fyne.io/systray`（Windows では cgo なしでビルドできる）
- **ビルド成果物**: 単一の静的 exe（`CGO_ENABLED=0`）

## 主要ライブラリ

- `golang.org/x/sys/windows` — Win32 API の呼び出し（`internal/platform` だけで使う）
- `fyne.io/systray` — タスクトレイのアイコンとメニュー（`internal/tray` だけで使う）
- それ以外は標準ライブラリだけで済ませる（依存を最小限にし、exe のサイズと配布の手間を抑えるため）。cgo が必要な依存は追加しない

## 開発標準

### 型安全とエラー処理
- Win32 呼び出しの戻り値は必ず確認し、`error` として呼び出し元へ返す
- `panic` は起動時の致命的な初期化失敗にだけ使う

### コード品質
- `gofmt` / `go vet` を通す
- 時刻は `time.Now()` を直接呼ばず、`Clock` インターフェースで受け取る（テストで時間を進められるようにするため）

### テスト
- 標準の `testing` パッケージを使う
- アイドル判定と移動方向のロジックは、偽の Clock と偽のマウスでユニットテストする
- 実際に `SendInput` を呼ぶ部分は手動で確認する（自動テストの対象外）

## 開発環境

### 必要なツール
- Go 1.26 以上（Windows 上で開発するか、`GOOS=windows` でクロスコンパイルする）

### よく使うコマンド
```bash
# 実行: go run ./cmd/mousemover
# ビルド: CGO_ENABLED=0 go build -ldflags "-s -w -H=windowsgui" -o dist/mousemover.exe ./cmd/mousemover
# テスト: go test ./...
# 静的解析: go vet ./...
```

## 主要な技術的判断

- **Go を採用**: クロスコンパイルが簡単で、ランタイムなしの単一 exe になる。Win32 API も cgo なしで呼べる。Python（PyInstaller）や Node.js（pkg）は exe が大きく、ウイルス対策ソフトに誤検知されやすい。Java / Kotlin は JRE が要る。Rust でも同じことはできるが、この規模なら Go のほうが開発の手間が少ない
- **アイドル検知は低レベルマウスフックを主、カーソル位置のポーリングを補助にする**: クリックやホイールも操作として数えるため、フック（`WH_MOUSE_LL`）が必要になる。キーボード入力も数えてしまう `GetLastInputInfo` は使わない。1 秒ごとのポーリングは、UIPI などでフックが取りこぼしたときの補助（2026-11-15 更新: idle-mouse-mover の設計で変更）
- **自分が動かしたカーソルを区別する**: `SendInput` の `dwExtraInfo` に固有の署名を付け、フックでは署名付きのイベントを無視する。ポーリングでは、自分が動かしたあとの位置を「既知の位置」として扱う
- **タスクトレイに常駐する GUI アプリにする**: `-H=windowsgui` でビルドし、コンソールは出さない。終了はトレイのメニューから行う。起動時のエラーはメッセージボックスで表示する（2026-11-15 更新: 要件でタスクトレイ常駐に決まったため）
